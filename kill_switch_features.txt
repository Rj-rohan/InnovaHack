THE KILL SWITCH - FEATURE PLAN
Problem Statement 2 (Fintech Domain)

CORE IDEA
Build a smart contract wallet that sits between the AI agent and real money. The agent never holds keys directly - it only gets permission to trigger actions inside limits we set on-chain. If the agent misbehaves, gets hacked, or just goes rogue, the contract itself refuses the transaction, and the owner can freeze everything instantly, even mid-transaction.

1. POLICY-ENFORCED SMART WALLET (Core Requirement 1)
- Deploy a smart contract wallet (using ERC-4337 account abstraction or a Safe/Gnosis Safe with a custom module) that the agent interacts with instead of a raw EOA.
- Spend limits (per-transaction cap, daily cap, rolling 24hr cap) are written into the contract, not into the agent's prompt or code.
- Every transaction request from the agent gets checked against these limits on-chain before it executes. If it fails the check, the transaction reverts - no exceptions, no "the agent forgot to check."
- This proves enforcement doesn't depend on the agent cooperating - even a compromised or adversarial agent physically cannot move funds outside the policy.

2. ALLOWLISTED COUNTERPARTIES (Core Requirement 2)
- Maintain an on-chain allowlist (simple mapping of approved addresses) that only the owner can update.
- Any transaction to an address not on the list is blocked at the contract level, regardless of what the agent "thinks" it's doing.
- Bonus: allow categories/tags for counterparties (e.g. "vendor", "gas refill", "exchange") so the owner can approve groups instead of one address at a time.

3. OWNER KILL SWITCH (Core Requirement 3)
- A single `pause()` function callable only by the owner (or a small multisig for extra safety) that immediately halts all agent transactions.
- Works as a circuit breaker pattern - once paused, every function the agent can call checks a `paused` flag first and reverts if true.
- Include an `unpause()` so the owner can resume once they've reviewed what happened.
- Optional: a "throttle" mode between full-stop and full-access, where the owner can drop the agent's limits to near-zero without fully freezing it (useful if we want partial ops to continue).

4. IN-FLIGHT REVOCATION (Bonus)
- Use session keys (ERC-7715 style or a custom signer-revocation mapping) so the agent's permission to act can be pulled mid-flow, even if a multi-step transaction is already underway.
- For multi-step / multi-call transactions, check the pause flag and allowlist status before EVERY sub-call, not just at the start - so revoking access stops execution between steps, not just before the first one.
- This is the hardest part to demo well, so we should build this early and test it doesn't just "block new transactions" but actually kills something already running.

5. UNSUPERVISED AGENT DEMO (Core Requirement 4)
- Build a simple AI agent (LangChain/basic LLM agent loop is enough) that runs on its own and periodically decides to send payments.
- Script three demo scenarios live:
  a. Normal operation - agent sends a small approved payment to an allowlisted address, succeeds.
  b. Attack attempt - agent (simulating a bug/prompt injection) tries to send to a non-allowlisted address or exceed its spend cap - contract reverts, agent's transaction fails on-chain, not because the agent "decided not to."
  c. Owner freeze mid-execution - while the agent is mid-loop attempting a legitimate-looking transaction, owner hits pause from a dashboard/CLI, and the in-flight action gets blocked instantly.
- Show contract-level logs/events (SpendLimitExceeded, CounterpartyNotAllowed, AgentPaused) so judges can see enforcement happening outside the agent, not inside its reasoning.

6. OWNER DASHBOARD (Nice-to-have, helps demo)
- Small frontend (React) showing: current spend limits, allowlist, live transaction attempts (approved/blocked), and one big red "FREEZE AGENT" button.
- Makes the live demo much more convincing to judges than reading contract calls off a terminal.

TECH STACK (proposed)
- Solidity smart contract wallet (Safe + custom Zodiac-style module, or a minimal custom contract if time is short)
- Hardhat/Foundry for local testing and deployment to a testnet (Sepolia)
- Simple agent loop in Python/JS calling the wallet through a library (ethers.js/web3.py)
- React dashboard + ethers.js for the freeze button and live status
